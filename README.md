# settlement-quest

Reproducible fixture and regression suite for a weekly rewards settlement,
payout and notification flow. Built for the MUST Company AI-Native Product QA
Engineer quest assessment.

**Defect under investigation:** [SETL-001](docs/defect-report-SETL-001.md) — the
settlement period is computed from local-time midnight instead of UTC and its
upper bound is inclusive, so every run both overpays and underpays while
reporting success.

No dependencies. No network. No live financial system.

---

## Run it

Requires Node 20 or newer (built and verified on v22).

```bash
cd settlement-regression-quest

# See the defect
IMPL=buggy node src/cli/run-settlement.js

# See the corrected behaviour
IMPL=fixed node src/cli/run-settlement.js

# The regression gate: fails on the faulty build, passes on the fix
IMPL=buggy npm test     # 13 pass, 4 fail  -> TC-05, TC-06, TC-07, TC-08
IMPL=fixed npm test     # 17 pass, 0 fail

# Regenerate every file in results/ from a clean run
node scripts/capture-evidence.js
```

## Design note

One engine, two window implementations, selected by the `IMPL` environment
variable. That is not a testing convenience — it is the shape of the root cause.
SETL-001 lives entirely inside `settlementWindow()`, so swapping that one
function is both how the defect is demonstrated and how it is fixed.

## Scope and honesty

The rewards service is the fictional one defined by the quest brief. It is not a
description of any live MUST Company product, and nothing here reflects any
real system's code, data or incident history. No employer data, credentials,
keys or customer records appear anywhere in this project.
