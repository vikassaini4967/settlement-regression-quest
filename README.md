# settlement-quest

Reproducible fixture and regression suite for a weekly rewards settlement,
payout and notification flow. Built for the MUST Company AI-Native Product QA
Engineer quest assessment.

**Defect under investigation:** [SETL-001](docs/defect-report-SETL-001.md) — the
settlement period is computed from local-time midnight instead of UTC and its
upper bound is inclusive. Every run settles the wrong tasks while reporting
success, and fixing the window on its own would lose a week of them.

No dependencies. No network. No live financial system.

---

## Run it

Requires Node 20 or newer. CI runs Node 20 and 22; the evidence in `results/` was
captured on v25.

```bash
cd settlement-regression-quest

# See the defect
IMPL=buggy node src/cli/run-settlement.js

# See the corrected behaviour
IMPL=fixed node src/cli/run-settlement.js

# See what it does across weeks, and on the week the fix ships
node src/cli/run-cutover.js

# The regression gate: fails on the faulty build, passes on the fix
IMPL=buggy npm test     # 18 pass, 4 fail  -> TC-05, TC-06, TC-07, TC-08
IMPL=fixed npm test     # 22 pass, 0 fail

# A real local-time bug: invisible under UTC, caught elsewhere
TZ=UTC IMPL=localtime npm test          # 22 pass, 0 fail
TZ=Asia/Seoul IMPL=localtime npm test   # 16 pass, 6 fail

# Regenerate every file in results/ and check the claims made about them
node scripts/capture-evidence.js
```

## Design note

One engine, with the build selected by the `IMPL` environment variable. A build
chooses the window and whether the task-ID guard is on. That is not a testing
convenience — it is the shape of the root cause. SETL-001 lives entirely inside
`settlementWindow()`, so swapping that one function is how the defect is
demonstrated.

Cases that describe what happens between builds, such as the week the fix ships,
name their builds directly and give the same result under every `IMPL`.

## Scope and honesty

The rewards service is the fictional one defined by the quest brief, and all
users, tasks and amounts are synthetic. It is not a description of any live MUST
Company product, and nothing here reflects any real system's code, data or
incident history. No employer data, credentials, keys or customer records appear
anywhere in this project.
